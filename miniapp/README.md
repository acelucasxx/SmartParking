# 小程序

原生微信小程序 + TypeScript（MP-01 骨架）。用微信开发者工具打开 `miniapp/` 目录。

## 目录

| 路径 | 内容 |
| --- | --- |
| `miniprogram/api/client.ts` | 请求核心：会话、静默登录（并发只登录一次）、登录失效自动重登并重试一次、统一信封解析、PATCH 改写 |
| `miniprogram/api/errors.ts` | 错误码表与处理方式 `errorAction`：`relogin` / `banned` / `leave` / `support` / `retry` / `show` |
| `miniprogram/api/types.ts` | 契约中多个页面共用的类型 |
| `miniprogram/api/index.ts` | 接入 `wx.request` / `wx.login` / 本地存储，导出全局 `api`；`onBanned` 监听账号停用 |
| `miniprogram/mock/` | 不连后端时的模拟数据与接口 |
| `miniprogram/components/` | 基础组件：`status-badge` 状态徽标、`battery-icon` 电量图标、`confirm-dialog` 确认弹窗（已在 `app.json` 全局注册） |
| `miniprogram/utils/format.ts` | 徽标文案、电量与信号分格、车位有无车、卡片标题、时间与有效期（按东八区）、幂等键 |
| `miniprogram/home/` | 车位首页的逻辑：列表与快捷控制的编排（`controller.ts`）、卡片渲染数据（`view.ts`） |
| `miniprogram/bind/` | 扫码绑定的逻辑：二维码取 SN、激活码、预检与绑定失败（`flow.ts`）、等待联网（`connect.ts`）、扫码（`scan.ts`） |
| `miniprogram/members/` | 成员管理与邀请家人的逻辑：有效期选项与自定义时间校验、名额、文案（`period.ts`） |
| `miniprogram/invite/` | 接受邀请的逻辑：token 检查、失效态、接受失败与接受后去向（`accept.ts`） |
| `miniprogram/device/` | 设备控制页的逻辑：三态主按钮与指令阶段（`control.ts`）、轮询编排（`controller.ts`）、渲染数据（`view.ts`） |
| `test/` | 纯逻辑的单元测试（Node 内置测试框架，不依赖微信环境） |

## 用法

```ts
import { api, isApiError } from '../../api/index'

try {
  const cards = await api.get<DeviceCard[]>('/devices')
} catch (e) {
  if (isApiError(e) && e.action === 'leave') wx.switchTab({ url: '/pages/index/index' })
}
```

- 路径不含 `/api/app` 前缀。除 `auth: false` 的请求外都会先确保已登录。
- `wx.request` 不支持 PATCH：`api.patch()` 自动改成 `POST` + `X-HTTP-Method-Override: PATCH`，服务端按 PATCH 处理。
- 错误统一抛 `ApiError`，`message` 优先用服务端的提示，可直接展示；是否弹 toast 由页面决定（控制页把错误显示在按钮附近）。

## 登录与手机号授权

- 启动即静默登录（`wx.login`），不弹任何授权。
- 手机号在需要时才授权：扫码绑定等操作前调用 `requirePhone(当前页面路径)`（`auth/index.ts`），未授权时打开登录授权页 `pages/login`，授权后回到原页面。平台规范不允许启动时强制获取手机号。
- 授权前必须勾选同意《用户协议》《隐私政策》（`pages/agreement`）。按钮为 `getPhoneNumber|agreePrivacyAuthorization`，一次点击同时完成微信隐私授权；`app.json` 开启了 `__usePrivacyCheck__`，小程序后台需填写隐私保护指引（手机号、蓝牙、位置）。
- 协议文本在 `content/agreements.ts`，**目前是占位文本**，待 EXT-16 提供正式条款后替换，并修改 `AGREEMENT_VERSION`（已同意旧版的用户会被要求重新同意）。
- 账号停用（10010）时跳到 `pages/banned`，只保留联系客服与退出登录。

## 设备控制页

`pages/device/device?id=设备ID`（MP-04，PRD 6.1 第 3 页、6.2）。页面只渲染，判断都在 `device/`，可单测：

- 三态主按钮：在线时为抬杆 / 落杆（已抬杆时突出“落杆”，中途停止或状态未知时两个同等）；休眠或离线时，蓝牙已上线（`bleAvailable`）给“蓝牙控制”并附原因，否则只显示原因；故障或已停用时按钮禁用，给说明与客服入口。执行中按钮置灰，连点只提交一次。
- 只有到位才算成功：已下发 → 执行中（收到开闸中 / 关闸中时播放闸杆动画）→ 到位成功；遇阻、红外、电机故障、超时显示服务端的 `resultMessage`。服务端 15 秒判超时、对账最晚约 30 秒给终态，前端最多等 35 秒，之后提示到操作记录查看，不再卡在“执行中”。
- 刷新：停留期间每 5 秒刷新状态，执行中每 1 秒轮询指令；页面隐藏即停止。进入时设备上有未终结的指令会接着跟踪；被授权人看不到家人的指令时按设备状态等它结束。
- 网络异常保留旧数据并提示“状态可能不是最新”；授权到期 / 撤销、设备不存在时提示后回首页。
- 电量只显示百分比和图标，不做低电量提醒（PRD 6.2）。
- 蓝牙控制（MP-12）与操作记录（MP-10）的入口目前只提示“即将上线”。

## 车位首页

`pages/index/index`（MP-03，PRD 6.1 第 2 页）：

- 列表顺序按接口：作为主人的设备在前，被授权的在后。卡片带“我的 / 家人共享”标签；被授权人显示有效期（永久有效 / 有效期至 12-31 18:00，剩余不足 24 小时为“剩余 X 小时”）。
- 卡片上的快捷抬杆 / 落杆与控制页同一套规则（`device/control.ts`）：在线可控、执行中置灰、休眠 / 离线 / 故障 / 停用只显示原因。首页不放蓝牙入口，点卡片进控制页。
- 首页不定时刷新，每次进入与下拉时刷新；只有卡片上有指令在执行时每 1 秒查该指令，结束后刷新一次列表。结果显示在卡片上，下次进入页面清掉。
- 点击被拒按原因处理：状态变了就提示并刷新列表；授权到期 / 撤销时弹提示，刷新后卡片消失。
- 空态引导扫码添加车位（先授权手机号）；列表加载失败给原因与重新加载；已有列表时刷新失败保留旧列表并提示。扫码绑定页在 MP-05，目前只提示“即将上线”。

## 扫码绑定

`pages/bind/bind` 与 `pages/bind/result`（MP-05，PRD 5.2、6.1 第 4–5 页）：

- 入口：首页“添加车位”扫码（只允许相机，`?sn=`）；或微信扫机身二维码直接打开绑定页（“扫普通链接二维码打开小程序”，`?q=` 为编码后的完整链接）。两种都只从链接里取 `sn` 参数，不认域名；也接受内容直接是 SN 的码。
- 先预检（`GET /bind/{sn}`）：本人已绑定直接进控制页；已有主人 / 已停用给客服入口；SN 不存在提示重新扫码。可绑定时若未授权手机号，用 `redirectTo` 去登录授权页，授权后回到绑定页（页面栈里不会出现两个绑定页）。
- 激活码输入自动去空格、转大写；错误显示剩余次数，连续输错 5 次锁定后输入框禁用并给客服入口。
- 绑定成功进入结果页：每 2 秒查状态，收到状态帧即“联网成功”；60 秒未联网提示检查电池与安装位置，可先离开，之后每 5 秒继续查。解绑后重新绑定的设备可能留着旧的 `statusRefreshedAt`，只认绑定前后 2 分钟窗口内的刷新。可顺手设置名称和车位号。
- **上线前（EXT-13）**：小程序后台“开发管理 → 开发设置 → 扫普通链接二维码打开小程序”添加规则，前缀与服务端 `DEVICE_QR_URL_TEMPLATE` 一致，小程序路径填 `pages/bind/bind`，并把域名校验文件放到该域名下。规则配好之前，只能从首页“添加车位”扫码绑定。

## 成员管理与邀请家人

`pages/members/members?id=` 与 `pages/members/invite?id=[&memberId=]`（MP-06，PRD 5.5、6.1 第 6–7 页），控制页对主人显示“成员管理”入口：

- 名额 = 生效成员 + 待接受邀请；满了“邀请家人”置灰并提示。成员显示备注与剩余有效期（尚未开始的显示开始时间）；邀请中的可撤回；成员可修改、撤销（二次确认）。
- 有效期：永久 / 1 / 7 / 30 天（邀请从接受时起算，修改从现在起算）/ 自定义起止（精确到分钟，止须晚于起和当前时间，起可以早于当前）。备注至多 32 字。
- 生成邀请后用 `open-type="share"` 发卡片，标题与路径用服务端返回的（路径带一次性 token）。token 只出现这一次，离开页面后只能撤回重邀。接受邀请页见下。

## 接受邀请

`pages/invite/accept?token=`（MP-07，PRD 5.5④⑧、6.1 第 8 页），从分享卡片打开：

- 预览显示设备名称、主人昵称、有效期、备注与卡片截止时间；接受不需要手机号。
- 失效态：已过期、已被他人接受、已撤销、自己已是成员（引导回“我的车位”）；另有自己发出的邀请、邀请不存在（token 格式不对或查无此邀请）。
- 接受时服务端再次校验，预览之后状态变了按错误码切到对应失效态；名额已满、设备已停用给出说明。
- 自定义有效期尚未开始的，接受后提示开始时间、回首页（到点才出现在列表里）；其余直接进控制页。

## 连后端还是用 mock

`miniprogram/config.ts`：

- `mock: false`（默认）：连 `apiBase`。本地后端用 `smartparking.wechat.mode=mock` 启动时，开发者工具里的任何 `wx.login` code 都能登录；开发者工具需勾选“不校验合法域名”。
- `mock: true`：不连后端。用户初始未授权手机号（手机号 code 规则同服务端 mock：1 开头的 11 位数字即该号码，`fail` 模拟失败）。内置 7 台示例设备：主人在线 / 被授权人休眠 / 主人离线 / 已停用，以及看控制页异常态用的演示设备“演示：遇阻”（每次 2 秒后遇阻失败）、“演示：超时”（15 秒后超时）、“演示：故障”。指令按时间推进：下发后 0.5 秒“已下发”、2 秒内“执行中”、2 秒后到位。接口返回副本，与真实接口一样改了不影响后台数据。扫码绑定可用 `SP2612000888`（激活码 `K7Q2M9XA`，绑定 3 秒后联网）和 `SP2612000666`（`K7Q2M9XB`，一直不联网，看 60 秒提示）；`SP2612000777` 为已被他人绑定。开发者工具里可用“编译模式 → 启动参数 `sn=SP2612000888`”直接打开绑定页。设备 1 有两位成员（永久 / 明天开始）和一张待接受邀请，名额上限 5。接受邀请页用启动参数 `token=…` 打开，各状态的演示 token 见 `mock/server.ts` 的 `MOCK_INVITE_TOKENS`。还没实现的接口返回“mock 未实现：方法 路径”，在对应页面任务里补。
