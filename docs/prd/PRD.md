**术语**

| 术语 | 含义 |
| --- | --- |
| 道闸 / 设备 | 安装在单个车位上的闸杆设备，由外壳、主板（闸板）、电机、电池、外挂 4G 模块组成 |
| DTU | 外挂 4G 模块（B100Ym-C1），只做串口与 MQTT 的透传，不解析协议 |

| 被授权人 | 主人授权的家人或亲友，在有效期内可控制设备 |
| 抬杆 / 落杆 | 抬杆 = 开闸放行；落杆 = 关闸占位。界面统一使用这两个词 |

## 2. 背景、目标与范围

一期只追求一件事：让业主从开箱到远程控制、再到授权家人，全程自助完成。

### 2.1 背景

- 现有道闸为单机版，只能用蓝牙或遥控器在现场控制。
- 网络版在主板外挂 4G DTU，通过 RS485 串口与闸板通信，使设备可被云端远程控制。
- 设备全部由业主自行购买、自行安装使用，**业务中不存在物业或车场运营方角色**。
- 设备为电池供电，业主自行给电池充电。

### 2.2 目标

1. 后台导入设备后，业主扫码即可绑定，无需任何网络配置。
2. 业主在小程序上远程抬杆、落杆，并看到真实执行结果。
3. 业主可把使用权按有效期授权给家人，可随时撤销，可转让设备。
4. 每一次控制都能追溯到操作人、时间、通道和结果。

### 2.3 范围

| 类别 | 内容 |
| --- | --- |
| 一期范围内 | 设备入库（单台 / 批量导入）；扫码绑定；远程抬杆 / 落杆及结果回执；设备状态显示（闸杆、在线、车位有无车、剩余电量、信号）；家人授权与有效期；设备转让；解绑；操作记录；故障告警；站内消息；蓝牙近场兜底（依赖固件，见第 12 章） |
| 一期范围外 | 物业 / 车场 / 经销商等多级组织；车位共享、预约、计费与支付；低电量提醒与换电工单；OTA 远程升级；数据大屏；4G 流量卡续费 |
| 为后期预留 | 指令通道字段可扩展（如新增定时自动落杆）；固件版本字段；工作模式（保持连接 / 深睡）字段 |

### 2.4 成功指标

| 指标 | 目标值 |
| --- | --- |
| 开箱到绑定完成 | 中位耗时 ≤ 3 分钟 |
| 在线设备远程控制成功率 | ≥ 99% |
| 从点击到显示“已到位” | P95 ≤ 5 秒，超时上限 15 秒 |
| 试点设备 14 天在线率 | ≥ 98% |
| 控制记录可追溯率 | 100% |

## 3. 用户角色与权限

系统只有两类人：小程序端的主人与被授权人，后台端的平台员工；平台员工不参与业主的日常控制。

### 3.1 角色定义

| 角色 | 端 | 数量约束 | 说明 |
| --- | --- | --- | --- |
| 主人（Owner） | 小程序 | 每台设备恰好 1 个 | 扫码绑定或接受转让后获得；一个用户可以是多台设备的主人 |
| 被授权人（Member） | 小程序 | 每台设备上限 N 个，默认 5，后台可配 | 通过主人的邀请加入，有效期内可控制 |
| 超级管理员 | 后台 | — | 全部权限，含账号与系统配置 |
| 运维 | 后台 | — | 设备入库、换件、禁用、告警处理、设备自检 |
| 客服 | 后台 | — | 查询设备与用户、强制解绑、处理抢绑申诉；不能远程控制业主设备 |

### 3.2 小程序端权限矩阵

| 操作 | 主人 | 被授权人（有效期内） |
| --- | --- | --- |
| 查看设备状态与电量 | ✓ | ✓ |
| 远程抬杆 / 落杆 | ✓ | ✓ |
| 蓝牙近场控制 | ✓ | ✓ |
| 查看操作记录 | 全部记录 | 仅本人的记录 |
| 修改设备名称、车位号 | ✓ | — |
| 邀请家人、设置有效期、撤销授权 | ✓ | —（**不能再分享**） |
| 转让设备 | ✓ | — |
| 解绑设备 | ✓ | — |
| 主动退出授权 | — | ✓ |

被授权人的有效期一旦到期或被撤销，该设备从其“我的车位”中移除，所有控制接口服务端立即拒绝。

## 4. 系统架构与设备身份

远程指令走“小程序 → 业务服务 → EMQX → 4G DTU → RS485 → 闸板”；蓝牙是不经过云端的近场兜底通道。

&#91;embedded content: 系统架构 · 远程链路与蓝牙兜底\]

DTU 不解析协议、不判断结果，所以“闸杆是否真的动了”只能由业务服务根据状态帧判定。

### 4.1 设备身份：四个标识，各管一件事

| 标识 | 来源 | 用途 | 可否变更 |
| --- | --- | --- | --- |
| IMEI | 4G 模块出厂，15 位 | 通信身份：MQTT 主题与客户端 ID | 换 4G 模块时由后台更新 |
| SN | 平台生成，印在机身二维码 | 业务身份：用户扫码、客服查询、绑定关系挂在 SN 上 | 终身不变 |
| 激活码 | 平台生成，8 位，只存哈希 | 防抢绑的第二因子，印在包装内 | 客服可重置 |
| 蓝牙 MAC | 主板出厂 | 小程序蓝牙连接时确认是这台设备 | 换主板时由后台更新 |

后台导入时 SN、IMEI、MAC 一起录入并建立关联。换件只改关联，业主的绑定和授权关系不受影响。

### 4.2 技术选型（建议）

| 层 | 选型 |
| --- | --- |
| 小程序 | 原生微信小程序 + TypeScript |
| 管理后台 | Vue 3 + Element Plus |
| 业务服务 | Java 17 + Spring Boot 3，模块化单体 |
| 设备接入 | EMQX 5.x 自建，持久会话 |
| 存储 | MySQL 8 + Redis 7 |
| 部署 | 云服务器 + Docker Compose，一期 4 核 8G 足够 |

## 5. 核心业务流程

七条流程共用一条原则：设备的控制权只来自“主人”一个源头，绑定、授权、转让、解绑都围绕它变化。

### 5.1 设备入库（后台）

1. 产线完成 DTU 参数预置（服务器、主题、一机一密）。
2. 运维在后台单台录入或批量导入 Excel / CSV，列固定为：SN、IMEI、蓝牙 MAC、型号、批次。
3. 系统校验：SN 格式与唯一；IMEI 15 位、Luhn 校验、唯一；文件内重复提示“与第 N 行重复”。
4. 校验通过的设备状态为“待激活”，系统生成激活码（只存哈希），导出“SN + 二维码 + 激活码”印刷文件，激活码仅在该次导出中可见。
5. 失败行单独列出行号与原因，可导出修正后重新导入。

二维码贴在机身上，激活码印在包装或说明书内，**不贴在机身**，防止路人拍照抢绑。

### 5.2 扫码绑定（主人首次激活）

1. 业主用微信扫机身二维码，直接打开小程序绑定页，SN 自动带入；也可在小程序内点“添加设备”扫码。
2. 未登录先微信登录并授权手机号。
3. 输入 8 位激活码。服务端三重校验：SN 存在 + 状态为待激活 + 激活码哈希匹配。
4. 同一 SN 连续输错 5 次锁定 30 分钟。
5. 校验通过后设备进入“已绑定”，当前用户成为主人。页面显示“等待设备联网”，收到设备上行状态帧即显示成功。
6. 60 秒内未收到上行：仍算绑定成功，提示“设备未联网，请检查电池与安装位置”，允许先离开。
7. 已被他人绑定：提示“该设备已有主人”，给出联系客服入口（持购买凭证申诉）。

### 5.3 远程抬杆 / 落杆

1. 用户点击抬杆或落杆。服务端校验权限（主人，或有效期内的被授权人）。
2. 设备已在目标状态：不下发，直接返回成功并记录。
3. 同一设备有未完成指令：返回“设备正在执行上一条指令”，按钮置灰。连点多次只产生一条指令。
4. 设备不在线：**不排队下发**，直接提示“设备离线，可在现场使用蓝牙”。理由：离线排队的指令可能在数分钟后突然执行，业主无法预期。
5. 在线：下发指令，界面显示“执行中”。服务端以状态帧判定结果：“开闸到位 / 关闸到位”为成功，电机故障、遇阻、红外防砸为失败并说明原因，15 秒未到位为超时。
6. 结果写入操作记录：操作人、角色、通道（远程 / 蓝牙）、动作、结果、耗时。

### 5.4 蓝牙近场兜底

1. 设备离线或用户主动选择“蓝牙控制”时进入。
2. 小程序向服务端申请票据（需联网和有效权限），票据 60 秒有效、一次性。
3. 小程序搜索并连接设备，写入票据和动作，读取执行结果。
4. 结果上报服务端落入操作记录；手机当时无网则缓存，恢复后补报。
5. 失败按原因给出动作：打开蓝牙、靠近设备、重试、联系客服。

前提：闸板固件需支持票据校验并提供 GATT 定义。固件未支持前，蓝牙入口不上线，见第 12 章。

### 5.5 分享授权（邀请家人）

1. 主人在“成员管理”点“邀请家人”，已达上限 N 人时按钮置灰并提示。
2. 选择有效期：永久 / 1 天 / 7 天 / 30 天 / 自定义起止时间（精确到分钟）；可填备注（如“爸爸”）。
3. 生成微信分享卡片发给对方。邀请 24 小时内有效、仅可被一人接受；未接受前占用名额，过期自动释放。
4. 对方点开卡片，登录后看到设备名称、主人昵称、有效期，点“接受”成为被授权人。
5. 主人可随时修改有效期或撤销授权，立即生效；被授权人收到站内消息。
6. 有效期到期：授权自动失效，释放名额。
7. 同一个人不能重复成为同一设备的被授权人；主人不能邀请自己。

### 5.6 转让设备

1. 主人点“转让设备”，阅读提示（转让后自己失去全部权限，现有被授权人全部清空）后生成转让卡片。
2. 转让卡片 24 小时有效，仅可被一人接受；接受前主人可取消。
3. 接收方点开后确认接收，成为新主人。原主人与全部被授权人失去权限并收到消息。
4. 新主人只能看到转让时刻之后的操作记录；历史记录保留在后台，用于审计。
5. 转让全过程不重置激活码，也不需要新主人到现场。

### 5.7 解绑与强制解绑

1. 主人解绑：二次确认后，设备回到“待激活”，全部被授权人失效。重新绑定仍需 SN + 激活码。
2. 客服强制解绑：用于抢绑申诉、二手转卖未转让等场景，必须填写原因，可选择是否重置激活码（重置后通过客服发送新码给申诉人）。
3. 所有解绑均写入后台操作日志，设备记录不删除。

## 6. 小程序功能需求

小程序一期共 13 个页面，底部导航为“车位 / 消息 / 我的”三项；技术上采用原生微信小程序，蓝牙兼容性最好。

### 6.1 页面清单

| # | 页面 | 优先级 | 主要内容 | 必须覆盖的异常态 |
| --- | --- | --- | --- | --- |
| 1 | 登录授权 | P0 | 微信登录、手机号授权、用户协议与隐私政策 | 拒绝授权、网络异常 |
| 2 | 车位首页 | P0 | 我的车位列表（主人的 + 被授权的），每张卡片带快捷抬杆 / 落杆 | 空态引导扫码、列表加载失败 |
| 3 | 设备控制页 | P0 | 闸杆状态、在线状态、车位有无车、剩余电量、信号、最近一次操作；大按钮抬杆 / 落杆 | 离线、休眠、故障、执行中、超时、遇阻 |
| 4 | 扫码绑定 | P0 | 显示 SN、输入 8 位激活码 | 码错误、连续输错锁定、已被他人绑定、SN 不存在 |
| 5 | 绑定结果 | P0 | 绑定成功 → 等待联网 → 联网成功；设置设备名称、车位号 | 60 秒未联网 |
| 6 | 成员管理 | P0 | 被授权人列表（备注、剩余有效期、状态）、已用 / 上限名额、邀请中的邀请 | 名额已满 |
| 7 | 邀请家人 | P0 | 选择有效期、填备注、生成分享卡片；修改有效期、撤销 | 自定义时间早于当前 |
| 8 | 接受邀请 | P0 | 设备名称、主人昵称、有效期、接受按钮 | 邀请已过期、已被他人接受、已撤销、自己已是成员 |
| 9 | 转让设备（发起 / 接收） | P0 | 转让风险提示、生成转让卡片、取消；接收方确认 | 卡片已过期、已取消 |
| 10 | 设备设置 | P0 | 名称、车位号、SN、固件版本、解绑；被授权人只看到“退出授权” | 解绑二次确认 |
| 11 | 操作记录 | P1 | 时间、操作人、动作、通道、结果；可按日期筛选；也显示遥控器、地感、延时自动关等非 App 触发的动作 | 空态 |
| 12 | 蓝牙控制 | P1 | 分步引导：申请票据 → 搜索 → 连接 → 执行 → 结果 | 蓝牙未开、未搜到、连接失败、票据失败 |
| 13 | 消息中心 + 我的 | P1 | 授权 / 撤销 / 转让 / 故障等站内消息；个人信息、帮助与客服 | 空态 |

### 6.2 关键交互规则

- **三态主按钮**：在线时主按钮为抬杆 / 落杆；休眠或离线时主按钮变为“蓝牙控制”，并附一行原因；故障时按钮禁用，显示故障说明与客服入口。蓝牙未上线前，离线状态只显示原因。
- **执行反馈**：点击后按钮进入“执行中”，收到“开闸中 / 关闸中”时显示闸杆动作动画，到位后显示成功。只有到位才算成功。
- **状态刷新**：控制页停留期间每 5 秒刷新，执行中每 1 秒轮询结果。
- **电量显示**：只显示剩余电量百分比和电量图标，**不做低电量提醒**。设备未上报电量时显示“—”。
- **有效期展示**：被授权人的卡片显示“有效期至 2026-12-31 18:00”或“永久”；剩余不足 24 小时时显示为“剩余 X 小时”。
- **角色标识**：车位卡片用小标签区分“我的”与“家人共享”。
- **消息通知**：一期以站内消息为准；微信订阅消息（授权成功、被撤销、转让完成、设备故障）待小程序类目与模板审核后接入。

## 7. 管理后台功能需求

后台一期 9 个模块，服务对象是厂家内部的运维和客服；不设物业或车场层级，设备直接挂在业主名下。

| 模块 | 优先级 | 功能 | 使用角色 |
| --- | --- | --- | --- |
| 登录与账号安全 | P0 | 账号密码登录；连续失败锁定；会话超时 | 全部 |
| 仪表盘 | P1 | 设备总数、已激活数、在线 / 休眠 / 离线 / 故障分布；今日指令数与成功率；未处理告警数 | 全部 |
| 设备入库 | P0 | 单台录入；批量导入（模板下载、异步处理、导入记录、失败行导出）；导出“SN + 二维码 + 激活码”印刷文件 | 运维 |
| 设备管理 | P0 | 列表（按 SN / IMEI / 手机号 / 绑定状态 / 在线状态筛选）；详情（实时状态、电量、信号、固件、主人、被授权人及有效期、指令记录、告警、事件流） | 运维、客服 |

| 指令审计 | P0 | 全量指令流水：时间、设备、操作人、角色、通道、动作、结果、耗时、原始帧；筛选与导出 | 运维、客服 |
| 告警中心 | P0 | 电机故障、遇阻、红外防砸、连续 3 次指令超时、离线超 24 小时；同设备同类 30 分钟内合并；标记处理与备注 | 运维 |
| 系统设置 | P0 | 账号与角色权限；后台操作日志；业务参数：被授权人上限（默认 5）、邀请 / 转让卡片有效期（默认 24 小时）、指令超时（默认 15 秒）、休眠 / 离线判定窗口（默认 10 分钟 / 24 小时） | 超级管理员 |

后台不提供“替业主远程抬杆 / 落杆”的入口；设备自检只发查询类指令，不动闸杆。如确需远程处置，应单独立项，并要求二次审批与业主知情。

## 8. 设备通信需求

云端自己编解 RS485 帧、自己确认执行结果；DTU 只是透传，收到命令回显不等于闸杆动了。本章按既有《设备接入契约 V1》整理，字节级细节以该契约与原始协议为准。

### 8.1 MQTT 接入

| 项 | 约定 |
| --- | --- |
| 上行主题 | `parking/up/{imei}`，云端订阅 `parking/up/+` |
| 下行主题 | `parking/down/{imei}`，每台 DTU 只订阅自己的 |
| QoS / 载荷 | QoS 1；载荷为 RS485 原始二进制字节 |
| 客户端 ID | `dtu-{imei}` |
| 鉴权 | 一机一密，平台生成、产线预置 |
| 端口 | 生产 8883（TLS），本地开发 1883 |
| 设备身份 | 从主题末段取 IMEI，未在库的 IMEI 一律拒收 |

### 8.2 RS485 帧

| 方向 | 结构 | 示例 |
| --- | --- | --- |
| 下行·查询状态 | `FD 00 地址 D0 C0 FD FA` | `FD 00 01 D0 C0 FD FA` |
| 下行·抬杆（开闸） | `FD 00 地址 03 FD FA` | `FD 00 01 03 FD FA` |
| 下行·落杆（关闸） | `FD 00 地址 05 FD FA` | `FD 00 01 05 FD FA` |
| 下行·查询版本 | `FD 00 地址 CF FD FA` | `FD 00 01 CF FD FA` |
| 上行·状态帧（8 字节） | 状态 + 动作原因 + 车位 | `FD 00 01 09 16 11 FD FA` = 开闸到位 / 平台指令 / 有车 |
| 上行·版本帧（7 字节） | `CF` + 版本号 | — |
| 上行·回显帧（6 字节） | 命令原样回显 | **不能当作成功** |

硬性规则：

- 查询指令数据位必须固定发 `C0`，发错会导致落杆静默失效。
- 协议无 CRC，只校验长度（5–8 字节）、首尾标志、状态码查表；查不到记为未知，不抛异常。
- 上下行同一长度含义不同，解析必须显式区分方向，不得靠长度猜。

### 8.3 码表与对外含义

| 状态码 | 含义 | 小程序显示 |
| --- | --- | --- |
| `09` | 开闸到位 | 已抬杆（放行） |
| `0C` | 关闸到位 | 已落杆（占位） |
| `19` / `1C` | 开闸中 / 关闸中 | 动作中 |
| `00` | 中间停止 | 动作被打断 |
| `E3` | 电机故障 | 故障，请联系客服 |

动作原因码用于操作记录中的“触发方式”：遥控器（01/02）、地感 / 雷达（03/04）、外部开关（06/07）、延时自动关（10）、遇阻（11，告警）、红外防砸（12，告警）、上电找零（15）、平台指令（16）。车位状态：`00` 无车，`11` 有车。充电相关码（17、22）忽略。

### 8.4 指令时序

1. 下发前比对当前状态，已在目标态则不下发。
2. 取设备级串行锁，先落库为“待下发”，再发布下行帧，状态变为“已下发”。
3. 每 300 ms 发一次查询，收到“开闸中 / 关闸中”为执行中，收到到位帧为成功（实测动作约 1.2 秒）。
4. 中途收到 `E3`、原因码 `11` / `12` 为失败并触发告警；15 秒未到位为超时。
5. 定时对账（每 15 秒）扫描未终结的指令，按设备最新状态补齐结果或判超时。

### 8.5 在线判定

| 状态 | 判据 | 小程序提示 |
| --- | --- | --- |
| 在线 | 10 分钟内有上报，或 MQTT 连接仍在 | 可远程控制 |
| 休眠 | 超过 10 分钟无上报，或收到断开事件 | 设备暂时无法远程控制，可用蓝牙 |
| 离线 | 超过 24 小时无上报 | 请检查电池电量和安装位置 |

判定来源有三个：状态帧、EMQX 连接事件、每 60 秒的定时扫描。休眠窗口必须大于 DTU 心跳（出厂 240 秒），否则正常设备会被误判为休眠。

### 8.6 工作模式与电量

- 默认“保持连接”模式：平均约 10 mA，20 Ah 电池约 83 天，指令秒级响应。深睡模式续航 2–3 年但指令延迟 10–60 分钟，一期不采用。
- **电量数据来源待确认**：现有 RS485 状态帧不含电量字段。需硬件方提供以下任一方案：闸板新增电量查询指令；DTU 心跳或注册包携带供电电压。未提供前，小程序电量显示为“—”。
- 电压换算为百分比的曲线由硬件方给出，云端只做查表。

## 9. 数据模型

核心是“设备—主人”一对一、“设备—被授权人”一对多；共 12 张业务表 + 5 张后台表，不设物业、车场、租户表。

| 表 | 关键字段 | 说明 |
| --- | --- | --- |
| `device` 设备 | sn（唯一）、imei（唯一）、ble\_mac、iccid、model、batch\_no、activate\_code\_hash、bind\_status（待激活 / 已绑定 / 已禁用）、owner\_user\_id、name、space\_no、fw\_version、work\_mode | 设备主档；换件只改 imei / ble\_mac |
| `device_runtime` 运行态 | device\_id、gate\_status、last\_reason、occupied、battery\_pct、signal、online\_state、last\_seen\_at | 最新状态，热数据同时放 Redis |
| `device_part_log` 换件记录 | device\_id、part（4G / 主板）、old\_value、new\_value、operator、reason | 追溯 IMEI / MAC 变更 |
| `app_user` 用户 | openid、unionid、phone（加密）、nickname、status | C 端用户 |
| `device_member` 授权 | device\_id、user\_id、remark、valid\_from、valid\_to（空 = 永久）、status（生效 / 已撤销 / 已过期 / 已退出）、granted\_by | 被授权人；唯一约束（device\_id, user\_id, 生效中） |
| `share_invite` 邀请 | token、device\_id、inviter\_id、valid\_from、valid\_to、remark、expire\_at、status、accepted\_by | 邀请卡片；待接受也占名额 |
| `device_transfer` 转让 | token、device\_id、from\_user、to\_user、expire\_at、status | 转让记录永久保留 |
| `ownership_log` 归属变更 | device\_id、type（绑定 / 转让 / 解绑 / 强制解绑）、from\_user、to\_user、operator、reason、at | 决定新主人可见记录的起点 |
| `control_command` 指令 | device\_id、user\_id、role、channel（远程 / 蓝牙）、action、status、result\_code、raw\_frame、issued\_at、finished\_at、idempotency\_key | 全量审计 |
| `device_event` 事件 | device\_id、gate\_status、reason、occupied、raw\_frame、at | 状态变化流水，按月分区，保留 ≥ 180 天 |
| `ble_ticket` 蓝牙票据 | ticket\_id、device\_id、user\_id、expire\_at、used | 60 秒一次性 |
| `alarm` 告警 | device\_id、type、level、first\_at、last\_at、count、status、handler、note | 同类 30 分钟合并 |
| `admin_user` / `role` / `operation_log` / `system_config` / `import_task` | — | 后台账号、权限、操作日志、可配参数、导入任务与失败行 |

权限判定在服务端完成：用户是 device.owner\_user\_id，或在 device\_member 中状态为生效且当前时间在 valid\_from 与 valid\_to 之间。

## 10. 非功能需求

安全是本产品的底线：闸杆是物理设备，误动作或被他人控制的代价远高于普通 App。

| 类别 | 要求 |
| --- | --- |
| 性能 | 远程控制从点击到到位 P95 ≤ 5 秒；接口 P95 ≤ 300 ms；一期按 5,000 台在线设备、峰值 50 条/秒指令设计 |
| 可靠性 | 指令幂等与设备级串行；服务重启后未终结指令由对账任务补齐；MQTT 断线自动重连；服务可用性 ≥ 99.5% |
| 设备安全 | 一机一密；生产环境强制 TLS；未登记 IMEI 拒收；DTU 参数仅产线预置，现场不可改 |
| 账号安全 | 绑定激活码只存哈希，连续 5 次错误锁定 30 分钟；邀请 / 转让 token 随机 ≥ 128 位、一次性、24 小时过期；所有权限判定在服务端完成，不信任前端 |
| 蓝牙安全 | 票据 60 秒、一次性、服务端判期；固件需校验 SN 与有效期，量产前需支持 HMAC 签名（见第 12 章） |
| 审计 | 每条控制指令记录操作人、角色、通道、结果、原始帧；后台高危操作（强制解绑、重置激活码、换件、禁用）写操作日志；审计数据保留 ≥ 180 天 |
| 隐私合规 | 手机号加密存储、界面脱敏；小程序隐私协议明示收集手机号、蓝牙、位置（蓝牙扫描所需）；被授权人只能看到主人昵称，看不到手机号 |
| 兼容性 | 小程序支持 iOS 13+ / Android 8+ 微信最新两个大版本；蓝牙覆盖 ≥ 20 款主流机型 |
| 运维 | 在线率、指令成功率、告警数三项监控看板；数据库每日备份，可恢复 7 天内任意时点 |

## 12. 待确认事项、风险与假设

最大的外部依赖是硬件方：电量上报和蓝牙票据校验两项不落地，对应功能就无法上线。

### 12.1 待硬件厂家确认

| # | 事项 | 影响 | 需在何时前确认 |
| --- | --- | --- | --- |
| 1 | 电量如何获取：闸板新增电量查询指令，或 DTU 心跳携带电压；电压–百分比曲线 | 小程序电量显示 | P0 结束 |
| 2 | 蓝牙 GATT Service / 特征值 UUID | 蓝牙控制能否开发 | P0 结束 |

### 12.2 风险

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 保持连接模式续航约 83 天，实际可能更短 | 用户频繁充电，电池耗尽后设备离线 | 试点期实测；小程序显示电量；保留深睡模式作为后期选项 |
| 蓝牙票据固件未校验 | 任何人近场可开闸 | 固件未支持前蓝牙入口不上线 |
| 地库信号弱 | 设备频繁休眠或离线 | 安装前用手机测信号；说明书给出安装要求；蓝牙兜底 |
| 二手转卖不走“转让” | 买家无法绑定 | 客服强制解绑 + 重置激活码流程 |
| 小程序类目与域名备案周期 | 上线延期 | P0 第 1 周同步启动 |

### 12.3 假设

- 被授权人上限默认 5 人，后台可调。
- 设备不在线时不排队下发指令（与参考方案的“离线排队”不同）。
- 转让时清空全部被授权人，由新主人重新邀请。
- 一个 DTU 只带一块闸板，RS485 地址固定为 1。
